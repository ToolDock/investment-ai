**【2026-09-23付けで廃止】この機能自体を使わなくなった。**
本番環境では実際の記事画像を再現できず(著作権上、実在の報道写真は使えない)、
汎用ストック写真の訴求力には限界があるという指摘から、ニュースは画像ではなく
見出し5本を並べる方式(`utils/components/news.py`の`show_news()`)に一本化した。
詳細はプロジェクトの設計doc「画像廃止とニュース見出し5本方式への統一_2026-09.md」
を参照。`utils/components/daily_report.py`からは`pick_news_image()`の呼び出しを
削除済み。このフォルダと`utils/news_images.py`は記録として残しているだけで、
アプリの動作には一切使われていない。

以下は廃止前の記録(2026-09-22時点)。

AI日報の見出しの上に添える画像。`utils/news_images.py` の `pick_news_image()` が、
その月・その日のニュースの内容に応じて `crash/`・`surge/`・`infection/`・`energy/`・
`tech/`・`policy/` のいずれかから、ファイルを1枚選んで返す。

## 選び方の方針(2026-09-22、§25-11で修正)

当初(§25-8〜§25-10)は「政治的に中立」「実在の出来事を具体的に描写しない」「抽象的な
金融イメージに留める」という方針で選んでいたが、本人から以下の指摘を受けて方針を
修正した。

- S&P500(米国市場)を扱う以上、米国会議事堂・星条旗・米国の風景などを使うことに
  何の問題もない。政治的文脈を避ける必要はなかった。
- 感染症のニュースでウイルスの画像(顕微鏡写真・3DCG)を使うのは妥当。避けるべき
  だったのは「コロナウイルスそのもの」を指す描写ではなく、**COVID-19という実在の
  固有の出来事だと特定できてしまう**描写(specific dates, named event)。ウイルス
  一般の画像は問題ない。
- ニュースなので、原因が分かるものは原因を写した画像を使う方が伝わる。暴騰が
  AI・テクノロジー株主導なら、AI・データセンター的な画像。暴落がエネルギー不安・
  地政学リスクなら、石油採掘施設・ガソリンスタンドの画像。抽象イメージより
  因果関係が伝わる画像を優先する。
- 暴落・暴騰の二択に絞らず、それ以外の重要なニュース(インフレ・利上げなど政策
  関連、テクノロジー主導の相場など)にも画像を加える。

一方で、以下は今回の修正後も変わらず避ける:

- 商標・ロゴ・実在銘柄のティッカー/実データが写り込んだ画面キャプチャ
  (Binance・TradingView等、企業ブランドが特定できるもの)
- 実在の紛争・戦争を報道写真的に具体的に描写したもの(このシナリオの60か月には
  戦争ニュースが存在しないため、使う場面自体が無い。§25-11で本人が確認済み)
- 実在の人物が悪い印象(パニック・絶望等)で写っている写真

## フォルダ構成とテーマ判定

| フォルダ | テーマ | 判定材料 |
|---|---|---|
| `crash/` | 暴落全般(原因が特定できないもの) | phaseが「暴落」で、下記テーマに該当しない場合のフォールバック |
| `surge/` | 暴騰全般(原因が特定できないもの) | phaseが「暴騰」で、下記テーマに該当しない場合のフォールバック |
| `infection/` | 感染症拡大 | headlineに「感染症」、またはreference(台本のみ)に「コロナ」 |
| `energy/` | エネルギー不安・地政学リスク | headlineまたはreferenceに「地政学」 |
| `tech/` | テクノロジー株主導の相場 | headlineに「テクノロジー主導」 |
| `policy/` | インフレ・利上げ・金融規制など政策関連 | headlineに「規制」、またはreference(台本のみ)に「インフレ相場」 |

`pick_news_image()` は、まずテーマ(infection/energy/tech/policy)に該当するか見出し
(headline)と台本のreference(実験のみ)から判定し、該当すればそちらを暴落・暴騰の
判定より優先する。該当しなければ、従来通りphaseが暴落・暴騰のときだけ`crash/`・
`surge/`にフォールバックする。

reference(台本の物語ラベル。例:「地政学ショック型」「2022年インフレ相場」)は
本番(`LiveProvider.timeline()`)には無い実験専用のフィールドだが、その分より緩い
条件(headlineのキーワード一致)だけで本番でも同じテーマ判定が働く設計にしてある
(「実験でできることは本番でもできる」という方針)。また、reference側の判定は
「急回復」局面(危機の直後、原因はもう和らいでいる場面)を除外している。収まった
危機のテーマ画像が回復局面まで居座らないようにするため。ただし急回復の月でも
headline自体にキーワードが出てくる場合(例:「地政学不安後退」)はそちらで拾う。

## 発生回数とファイル枚数を揃える注意点(2026-09-22の教訓、引き続き有効)

`pick_news_image()` は各フォルダの中身をファイル名順に並べて、そのテーマ(または
局面)の発生回数(実験)または日付のハッシュ(本番)でローテーションする。フォルダ
内の枚数が実際の発生回数と合っていないと、発生回数を超えた分は実験モードでは
構造的に出番が来ない(本番の日付ローテーションでしか出ない)。新しくテーマ写真を
追加・差し替える際は、`scenario_scripted.json`の該当テーマの発生回数を数えてから
枚数を決めること。現状の発生回数(60か月中):

- `infection/`: 2回(18・19か月目) → 2枚
- `energy/`: 2回(41・42か月目) → 2枚
- `tech/`: 4回(5・12・14・59か月目) → 3枚(2026-09-23時点。あと1枚あれば理想)
- `policy/`: 9回(23〜30・53か月目) → 3枚
- `crash/`・`surge/`: それぞれ60か月中4回ずつ(テーマに該当しない残り) → 4枚ずつ

## さらに写真を追加・差し替えたい場合

対応するフォルダ(`crash/`・`surge/`・`infection/`・`energy/`・`tech/`・`policy/`)に
画像ファイル(jpg/png/webp/svg)を置くだけでよい。コード側の変更は不要(拡張子を
問わず自動的に読み込まれる)。新しいテーマを追加したい場合は`utils/news_images.py`の
`THEME_KEYWORDS`にキーワードを追加し、同名のフォルダを作る。

Pixabay・Pexelsのライセンス(いずれも商用利用可・帰属表示不要。2026-09-22に公式
ページで確認済み)に沿った検索キーワードの例:

- **infection/**: "virus microscope", "coronavirus 3d render", "pandemic city"
- **energy/**: "oil rig", "gas station refueling", "oil refinery aerial"
- **tech/**: "data center server room", "AI technology blue", "server racks"
- **policy/**: "us capitol building", "american flag", "federal reserve building"
- **crash/**: "stock market crash", "financial crisis", "red arrow down chart"
- **surge/**: "stock market rally", "bull market", "green arrow up chart"

選ぶ際に注意してほしい点(ライセンス上・内容上の制約):

- 実在の人物が写り込んでいる写真は避けるか、その人物が悪い印象(パニック・絶望等)
  で描かれていないか確認する
- 特定企業のロゴ・商標(取引所名、個別銘柄のティッカー等)が写り込んでいる写真は
  避ける
- 実在の紛争・災害を報道写真のように具体的に描写した写真は避ける。ただし
  ウイルス・石油施設・議事堂・国旗など、特定の一回性の出来事を指さない一般的な
  画像は問題ない(§25-11で方針修正)
- 素材そのものを無加工でポスター等として転売しない、という制約があるが、
  アプリ内表示は問題ない

## `_unused/` フォルダについて

2026-09-22に本人が集めた29枚のうち、まだどのテーマにも採用していない写真を
そのまま置いてある(一部は採用済みだが予備として残したもの、一部は上記の理由で
引き続き除外)。`pick_news_image()` はテーマフォルダの中しか見ないので、ここに
ある画像はアプリの動作には一切影響しない。
